# opencode-statuskit 2.0.3

Adds the **OpenCode 1.18.x legacy line (1.0.0)**. The OpenCode 2.x plugin behavior is unchanged from 2.0.2.

## Highlights

- **OpenCode 1.x support**: `legacy/opencode-1/` restores the V1 plugins and installers, frozen at 1.0.0.
- **Version dispatch**: the root `install.sh` reads `opencode --version` and runs the 1.x or 2.x installer.
- **Legacy tests**: V1 title/done unit tests and installer tests run with the existing suite.
- **Upgrade docs fixed**: tag-based clones now use `git fetch --tags` + `git checkout <tag>` instead of `git pull`.
- **Windows guard**: `install.ps1` warns and stops on native Windows OpenCode 1.x, directing users to WSL.
- **Docs**: English/Chinese README sections for the legacy line, `tui.json`, `tui-plugins/`, and `OPENCODE_DISABLE_TERMINAL_TITLE`.

## Install

### OpenCode 2.x

```sh
git clone https://github.com/emmmdty/opencode-statuskit.git
cd opencode-statuskit
./install.sh
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

### OpenCode 1.x legacy

Linux, macOS, WSL:

```sh
cd opencode-statuskit
./install.sh                      # auto-detects 1.x
# or:
./legacy/opencode-1/install.sh
```

Restart OpenCode 1.x after installing. Native Windows 1.x is not supported; use WSL.

## Upgrade

### From 2.0.2 to 2.0.3

Re-run the installer from the new version. Do not uninstall first.

If you cloned a tag:

```sh
cd opencode-statuskit
git fetch --tags
git checkout v2.0.3
./install.sh
```

If you cloned `main`:

```sh
git pull
./install.sh
```

If you downloaded a tarball, download the new `opencode-statuskit-2.0.3.tar.gz` and `SHA256SUMS`, verify, extract, then run `./install.sh` from the new directory.

On Windows, re-run `install.ps1` after updating the checkout or extracting the new zip.

### OpenCode 1.x legacy

The legacy line is frozen at 1.0.0. There are no routine upgrades.

## Known limits

- Native Windows OpenCode 1.x is not supported; use WSL.
- macOS TUI behavior in Terminal/iTerm2 is not yet verified.
- The 1.x line is frozen at 1.0.0; no new features.
- npm packages are prepared but not published.
- In tmux, the pane title changes; the outer title depends on `set-titles`.
